# Alpha 稳定性与真机验收记录

对应 Issue：#18

这份记录区分自动化验证与 Windows 真机验证。没有真实运行证据的项目保持未验证，不用模拟数据冒充真机结果。

## 已实现的恢复与可观测性

- 启动时保留并展示 `recording`/`interrupted` 会话；异常退出不会删除已有时间线。
- 启动时自动扫描未回收会话的 `audio_chunks.pending`，重新排队转写；音频文件缺失会标记为失败并提示用户。
- 失败音频可通过恢复提示中的“重试音频”入口重新排队，失败模型调用会在启动时物化为对应的失败回答、材料或跨会话综合记录；各功能沿自己的历史重试入口执行。
- 录制状态持续展示关键帧数量、会话存储量、磁盘剩余空间、转写实时系数、校订积压、待转写/失败转写数量、失败模型任务数量、CPU、GPU 和内存。
- GPU 指标只在本机可用 `nvidia-smi` 时显示；否则明确显示“未检测”，不伪造零值。
- 磁盘剩余空间低于 512 MiB 时显示“磁盘空间告警”。
- 来源故障、模型调用、模型证据和时间线事件沿既有本地审计链保存。

## 已知限制

- 进程已经退出后无法继续同一组实时采集线程；应用会保留中断会话、已写入时间线和待转写音频，并在重启后恢复可恢复部分。
- 没有 NVIDIA 驱动或 `nvidia-smi` 的机器不能提供 GPU 利用率/显存指标，界面显示“未检测”。
- 物理设备拔出后的缺失区间不会被伪造为有效证据；来源故障会记录为时间线事件并提示用户。
- 真机验收记录需要设备、网络和存储权限，不能由离屏测试替代。
