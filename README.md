# 境织 · JINGZHI

境织是一款 Windows 优先、Python 实现、本地优先的桌面上下文助手。它把屏幕、声音和时间线组织成可回看、可追问的上下文，适用于学习、会议、办公、资料研究和技术排障。当前版本验证最关键的闭环：

1. 持续采集屏幕，但仅保存发生明显变化的关键帧；
2. 分轨采集系统声音和麦克风；
3. 使用本地 Whisper 模型生成接近实时的字幕；
4. 所有内容使用同一个会话相对时间轴；
5. 提问时取最近字幕和相邻关键帧交给可配置的 OpenAI 兼容多模态模型；
6. 会话结束后生成总结、知识点和可确认的错误或疑问。

摄像头、OCR、向量检索和自动识别课程起止暂不放入第一版。它们都能后加，且不会改变当前的数据主键和时间轴设计。

## 架构与模块边界

```text
屏幕采集线程 ──关键帧──┐
                       │
系统音频线程 ──音频块──┼── SQLite 元数据 + 会话文件目录
                       │
麦克风线程 ───音频块───┘
       │
       └── 转写线程 ──带起止时间的字幕

用户提问
   └── 上下文组装器
          ├── 最近 8 分钟字幕
          └── 与提问时刻最接近的 4 张关键帧
                 └── 多模态模型 ──回答

会话结束
   └── 全部字幕 ──结构化总结/知识点/错误与疑问
```

代码职责如下：

| 模块 | 单一职责 | 不负责 |
|---|---|---|
| `capture/screen.py` | 截屏、变化检测、关键帧落盘 | OCR、模型调用 |
| `capture/audio.py` | WASAPI 系统回环与麦克风分轨、分块、降采样 | 转写、混音 |
| `transcribe.py` | 消费已落盘音频块并写入字幕 | 设备采集、界面更新 |
| `clock.py` | 产生单调递增的会话相对时间 | 系统时间校准 |
| `database.py` | 元数据、索引和状态持久化 | 大文件内容存储 |
| `context.py` | 按时间窗口组装问题上下文 | 回答问题 |
| `llm.py` | 模型供应商适配和输出约束 | 采集与检索策略 |
| `session.py` | 会话生命周期和工作线程协调 | 控件绘制 |
| `ui.py` | 桌面交互和跨线程信号 | 业务数据处理 |

关键约束是“先落盘，再进入下游队列”。转写或模型调用失败时，音频和关键帧仍然存在，可以重试；界面退出不会使采集数据只留在内存中。

## 技术选型

| 领域 | MVP 选型 | 原因 | 后续替换条件 |
|---|---|---|---|
| 桌面界面 | PySide6 | Python 原生开发效率高，Qt 的跨线程信号适合采集程序 | 若要深度使用 Windows 原生悬浮层，再考虑 WinUI 3 前端 |
| 屏幕采集 | `python-mss` | 接口简单，足以验证关键帧策略 | 需要高帧率、指定窗口或受保护内容时改 Windows Graphics Capture |
| 图像变化 | 16×16 average hash | 成本低、实现透明 | 频繁误判时增加 SSIM、窗口标题和 OCR 变化率 |
| 音频采集 | 系统声音使用 SoundCard/WASAPI loopback；麦克风使用 python-sounddevice/PortAudio | 避免部分 Windows 麦克风触发 SoundCard 的设备格式断言 | 更复杂的设备选择可再封装原生 WASAPI 客户端 |
| 音频存储 | 16 kHz 单声道 FLAC | 对语音识别足够，显著小于 48 kHz 双声道 PCM | 需要高保真回放时另存原始音轨 |
| 字幕 | `faster-whisper` | 本地运行，支持 VAD 和时间戳 | 追求更低延迟时加入流式确认/回滚策略 |
| 数据库 | SQLite WAL + FTS5 | 无服务、易备份，适合单机时间轴 | 多设备同步后再引入服务端数据库 |
| 多模态问答 | 可配置 Base URL 的 OpenAI 兼容适配层 | 同时支持 Responses API 和 Chat Completions | 非 OpenAI 兼容协议另加适配器 |
| 向量检索 | MVP 不启用 | “刚才这一步”首先是时间检索，不需要向量库 | 需要跨多节课语义召回时增加 `sqlite-vec`，保留 FTS5 混合检索 |

## 数据结构

数据库位于 `data/jingzhi.sqlite3`，媒体位于 `data/sessions/<session-id>/`。

| 表 | 关键字段 | 含义 |
|---|---|---|
| `sessions` | `id`, `started_at_utc`, `status` | 一次学习、会议或工作会话 |
| `frames` | `session_id`, `ts_ms`, `path`, `perceptual_hash` | 关键帧及其相对时间 |
| `audio_chunks` | `source`, `start_ms`, `end_ms`, `state` | 系统音频/麦克风分块及处理状态 |
| `transcript_segments` | `source`, `start_ms`, `end_ms`, `text` | 与音频块对齐的字幕 |
| `transcript_fts` | `segment_id`, `text` | 后续全局关键词检索入口 |
| `questions` | `asked_at_ms`, `context_start_ms`, `answer` | 问题、答案及使用的时间窗口 |
| `artifacts` | `kind`, `content_json`, `model` | 总结、知识点和错误提取结果 |

时间对齐只使用 `time.monotonic_ns()` 派生的 `ts_ms`。UTC 时间仅用于展示和跨会话排序。这样即使系统校时或用户修改时间，字幕与截图也不会错位。

## 性能与容量设计

- 屏幕默认每秒检查一次，只有 average-hash 汉明距离达到阈值才保存 WebP。PPT 课程通常远低于每秒一张；视频课程仍可能频繁保存，后续应增加帧率上限和相似帧合并。
- 采集以 48 kHz 进行，落盘前混为单声道并降至 16 kHz FLAC。两条语音轨的实际容量取决于内容和静音比例；容量上限应在真机试用后测量，不应直接按经验写死。
- 转写队列上限为 16 个音频块，防止模型明显落后时无限占用内存。队列满后，新音频块仍会落盘并保留为 `pending`，同时给出告警；下一阶段应在启动时自动恢复这些待处理块。
- SQLite 使用 WAL，每次写入使用短连接并设置 10 秒忙等待，避免多个采集线程长期持有写锁。
- 问答只发送最多四张关键帧；字幕默认回看八分钟。这样可控制图像上传量和模型上下文长度。

建议在目标电脑上记录 60 分钟真实网课，测量以下指标后再调参：平均关键帧数/分钟、音频存储 MB/小时、转写实时系数、字幕端到端延迟、队列峰值、CPU/GPU/内存占用。

## 隐私设计

默认原则是“本地采集、本地转写、按需上传”：

- 屏幕、音频、字幕和数据库均保存在本机；
- 只有用户主动提问或生成总结时才调用云模型；
- 提问只上传选中的关键帧和时间窗口字幕，不上传整段录屏或音频；
- API 密钥可从界面或环境变量提供，只保存在当前进程内存中，不写入数据库或配置文件；
- 正式版本必须增加排除应用/窗口列表，并默认排除密码管理器、隐私窗口、通知中心和指定浏览器标签；
- 必须提供明显的录制状态、暂停快捷键和“立即删除本次会话”；
- 删除功能需要同时清理媒体文件、普通表、FTS 影子表及备份，并说明 SQLite 删除后的取证残留风险；高敏感场景应使用整盘加密或每会话加密容器。

如果用于线下课程、会议或他人语音，使用者还需要遵守所在地法律和现场录音规则。

## 运行

Windows PowerShell：

```powershell
cd D:\Codebase\jingzhi
uv sync --extra dev
uv run jingzhi
```

首次启动会下载 Whisper `small` 模型。界面顶部可直接填写 `Base URL`、`API Key`、`Model`，并选择 `Responses API` 或 `Chat Completions`。点击“保存配置”后，Base URL、模型和接口类型写入 `data/provider.json`，API Key 单独写入 Windows 凭据管理器，不会以明文进入配置文件或 SQLite；下次启动会自动回填。测试连接成功以及正常关闭窗口时也会自动保存。没有 API 密钥时，本地采集和字幕仍可使用，提问与总结会给出明确错误。回答区域支持 Markdown，以及 `$...$`、`$$...$$`、`\(...\)` 和 `\[...\]` 形式的 LaTeX 公式；渲染资源均随应用保存在本地。

建议先点击“测试连接”。如果 Provider 返回网页源码，应用会给出简短提示，而不会把整页 HTML 显示到界面。开始记录前可以分别启用或关闭“系统声音”和“麦克风”；没有可用麦克风时，关闭麦克风仍可继续记录系统声音和屏幕。详细异常保存在 `data/logs/app.log`。

也可以使用环境变量提供默认值：

```powershell
$env:OPENAI_BASE_URL = "https://provider.example/v1"
$env:OPENAI_API_KEY = "your-key"
$env:OPENAI_MODEL = "your-vision-model"
$env:OPENAI_API_MODE = "chat_completions" # 或 responses
uv run jingzhi
```

有 NVIDIA GPU 时可在启动前设置：

```powershell
$env:WHISPER_DEVICE = "cuda"
$env:WHISPER_COMPUTE_TYPE = "float16"
```

执行核心测试：

```powershell
uv run pytest
```

## 分阶段开发计划

### 阶段 0：设备可行性验证（1～2 天）

- 枚举并实测用户电脑上的扬声器回环、麦克风和多显示器；
- 连续采集 60 分钟，确认无音频中断、时钟漂移和数据库锁错误；
- 记录容量、转写实时系数和字幕延迟基线。

验收条件：一小时课程可完整生成双轨音频、关键帧和按时间排序的字幕。

### 阶段 1：当前 MVP 闭环（3～5 天）

- 完善开始、暂停、继续、结束和异常恢复；
- 提问时展示实际引用的字幕区间和截图；
- 总结结果提供可编辑界面和 Markdown/JSON 导出；
- 增加会话浏览、回放跳转和删除。

验收条件：能针对“五分钟内老师刚讲的这一步”给出带时间依据的回答，并能在课后生成可追溯的总结。

### 阶段 2：检索与学习结构（约 1 周）

- 对字幕做章节切分和关键词提取；
- 采用 FTS5 + 向量的混合检索支持跨课程提问；
- 错题采用“题目、用户作答、纠正、知识点、来源时间、置信度”结构；
- 只有发现用户作答或明确纠正时才生成错题，避免把老师举例误判为用户错误。

验收条件：跨多节课检索时能返回来源会话、时间和关键帧，错题均可追溯到原始证据。

### 阶段 3：视觉与交互完善（1～2 周）

- 增加 OCR，并用窗口标题、OCR 差异和图像差异共同选择关键帧；
- 增加摄像头作为独立来源，明确关闭状态和权限；
- 增加全局快捷键、悬浮字幕、按住说话提问；
- 对公式和板书增加高分辨率局部截图。

验收条件：PPT、视频、手写纸面三类场景都能稳定提问，且用户能确认应用当前采集了哪些来源。

### 阶段 4：稳定性与发布（约 1 周）

- 进程崩溃后恢复未完成会话和 `pending` 音频块；
- 增加容量配额、保留期限、排除窗口、敏感内容检测和加密；
- 使用 PyInstaller 或 `pyside6-deploy` 打包，完成无 Python 环境安装测试；
- 增加 4～8 小时连续运行、设备切换、睡眠唤醒和无网络测试。

验收条件：异常退出不丢已落盘数据，隐私设置默认安全，普通用户可以安装并完成一节课。

## 当前骨架的已知边界

- “实时字幕”目前是 8 秒音频块完成后转写，实际延迟还包括模型处理时间；没有增量假设和文本回滚。
- `faster-whisper` 首次下载模型需要网络，CPU 上的 `small` 模型未必能在所有电脑上达到实时速度。
- SoundCard 官方列出了若干 Windows/WASAPI 已知问题，必须在目标声卡上实测；生产版本应保存设备 ID，不应永久依赖默认设备。
- 课后总结一次提交全部字幕，长课程可能超过模型上下文。下一步应实现章节级 map-reduce，并保留每段摘要到原字幕的映射。
- 目前没有保存模型请求中实际采用的 frame ID 列表，只保存时间窗口。正式审计和可复现回答需要新增 `question_context_items` 关联表。
- 应用退出时会等待剩余转写完成，长队列可能导致退出较慢。正式版本应将任务状态持久化并允许后台续跑。
